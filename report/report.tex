\section{Введение}

Данный проект представляет собой учебную задачу по разработке консольного приложения-архиватора
на основе алгоритма Хаффмана. Работа позволяет на практике освоить механизмы побитового
ввода-вывода, методы построения префиксных кодов переменной длины и принципы управления
динамическими структурами данных (бинарными деревьями) на языке C++.

\section{Постановка задачи}

Актуальность работы обусловлена необходимостью получения практических навыков
низкоуровневой обработки информации. Умение работать с битовыми кодами и побитовым
вводом-выводом, освоенное в ходе реализации алгоритма Хаффмана, имеет высокую практическую
ценность и востребовано в различных актуальных областях программной инженерии, требующих
эффективного управления памятью и ресурсами. При этом сам алгоритм Хаффмана является одним
из наиболее известных методов кодирования и широко применяется в различных форматах хранения
и передачи данных. Целью работы является разработка консольного приложения, использующего
алгоритм Хаффмана для уменьшения объёма хранимой информации без потери данных.

\textbf{Для достижения цели требуется решить следующие задачи:}

\begin{enumerate}
    \item Выполнить обзор существующих решений и изучить теоретические основы алгоритма
          Хаффмана.
    \item Спроектировать архитектуру приложения и его основные модули.
    \item Реализовать программный код для сжатия и восстановления исходных файлов.
    \item Провести тестирование разработанного решения на файлах различного типа и размера.
\end{enumerate}

\section{Обзор}

Сжатие без потерь (\textit{lossless compression}) применяется там, где критически важна абсолютная
точность восстановления исходных данных (тексты, программный код, исполняемые файлы). В
рамках данного проекта рассматриваются теоретические основы и подходы к реализации алгоритма
частотного кодирования Хаффмана.

\subsection{Теоретические основы алгоритма Хаффмана}

Метод основан на подсчёте частоты появления каждого символа в файле. Символам, которые
встречаются чаще всего, присваиваются самые короткие битовые коды, а редким символам~--- более
длинные. Связь между символами и кодами строится с помощью бинарного дерева. При этом
построенные коды обладают важным свойством префиксности (ни один код символа не является
началом (префиксом) кода другого символа). Например, если символ <<А>> закодирован как 01, то
ни один другой символ не может иметь код, начинающийся с 01. Главная сложность и особенность
классического алгоритма заключается в необходимости сохранять структуру дерева или таблицу
частот внутри сжатого файла, чтобы принимающая программа (декодер) могла правильно
восстановить данные.

\subsection{Подходы к реализации}

Существует множество открытых программных реализаций алгоритма Хаффмана, которые
различаются выбранными структурами данных, такими как~\cite{nayuki} для построения дерева
кодирования используется очередь с приоритетами: на каждом шаге извлекаются два узла с
наименьшим весом и объединяются в новый родительский узел. Для построения дерева кодирования
классическим подходом является использование очереди с приоритетами, что позволяет эффективно
извлекать два узла с минимальным весом и объединять их, создавая нового общего родителя.

\section{Описание предлагаемого решения}

Программа написана на языке C++ (стандарт C++17).

Логика программы разделена на четыре последовательных шага:

\begin{enumerate}
    \item \textbf{Подсчёт частот:} Чтение файла и сбор статистики появления каждого байта.
    \item \textbf{Построение дерева:} Создание бинарного дерева Хаффмана на основе полученных частот.
    \item \textbf{Создание таблицы кодов:} Обход дерева от корня к листьям для генерации новых битовых кодов.
    \item \textbf{Битовый ввод-вывод:} Упаковка данных в бинарный файл архива с помощью специального побитового буфера.
\end{enumerate}

Наибольшую сложность в проекте вызвало управление памятью при построении дерева Хаффмана.
Алгоритм требует постоянно извлекать из очереди два узла с минимальным весом, объединять их и
создавать для них нового общего родителя.

\section{Эксперименты}

Для оценки производительности и эффективности \textbf{алгоритма Хаффмана} был написан
специальный тестовый модуль на языке C++. В качестве исходных данных использовался набор из
шести файлов, представляющих различные типы информации. Текстовые данные разного объёма:
\texttt{small.txt} (содержит краткое содержание романа Л.\,Н.\,Толстого «Война и мир») и
\texttt{large.txt} (содержит полный текст романа «Война и мир»). Несжатые бинарные данные:
\texttt{binary.bin} (скомпилированный 64-битный исполняемый файл для ОС Linux в формате ELF).
Предварительно сжатые мультимедийные форматы и архивы: \texttt{compressed.zip}, \texttt{image.jpg},
\texttt{music.mp3}. Все тестовые файлы доступны в открытом репозитории проекта~\cite{repo}.

Для получения статистически достоверных результатов замеры времени проводились программно.
Все эксперименты проводились на следующей аппаратной и программной конфигурации:

\begin{enumerate}
    \item Процессор: Intel Core i5-13420H (12 ядер, базовая частота $\sim$2.1\,ГГц).
    \item Оперативная память: 16\,ГБ DDR4.
\end{enumerate}

Программная среда:

\begin{enumerate}
    \item ОС: Windows 11 Pro 64-разрядная.
    \item Среда выполнения: WSL2 (Windows Subsystem for Linux 2).
    \item Ядро Linux: 6.6.87.2-microsoft-standard-WSL2.
    \item Дистрибутив Linux: Ubuntu 24.04.1 LTS.
\end{enumerate}

Инструменты сборки и компиляции:

\begin{enumerate}
    \item Компилятор: g++ 13.3.0
    \item Стандарт языка: C++17
    \item Система сборки: CMake 3.20.
    \item Конфигурация сборки: Release.
    \item Флаги компиляции: \texttt{-std=c++17 -O2 -march=native}.
\end{enumerate}

Каждая операция (\textbf{сжатие~--- \texttt{encodeFile} и распаковка~--- \texttt{decodeFile}})
выполнялась в цикле по 10 раз для каждого файла. Замер времени осуществлялся с помощью
библиотеки \texttt{<chrono>}~\cite{chrono}.

На основе массива полученных временных интервалов программа автоматически рассчитывала:

\begin{enumerate}
    \item Среднее время выполнения операции (математическое ожидание).
    \item Среднеквадратичное отклонение (СКО) для оценки стабильности работы алгоритма.
\end{enumerate}

\textbf{Выводы.} Алгоритм демонстрирует высокую эффективность при работе с текстовыми данными.
Например, файл \texttt{large.txt} объёмом почти 1.5\,МБ был сжат до 0.9\,МБ. При обработке уже
сжатых форматов (\texttt{.zip}, \texttt{.jpg} и \texttt{.mp3}) размер файла ожидаемо остался
неизменным или незначительно увеличился. Результаты эксперимента, проведённого в автоматическом
режиме на серии из 10 запусков, подтверждают, что \textbf{алгоритм Хаффмана} показывает высокую
эффективность на избыточных данных (текстах) и демонстрирует предсказуемое, стабильное сжатие
текстовых файлов.

\section{Заключение}

В ходе выполнения работы получены следующие результаты:

\begin{enumerate}
    \item Спроектировано и реализовано программное решение на языке C++ для сжатия и точного
    восстановления файлов с использованием алгоритма префиксного кодирования Хаффмана
    (модули \texttt{encoder} и \texttt{decoder}).

    \item Разработан автоматизированный модуль тестирования для оценки скорости и стабильности
    работы реализованных алгоритмов.

    \item Проведена успешная экспериментальная проверка программы на наборе файлов различных
    форматов и объёмов.
\end{enumerate}
